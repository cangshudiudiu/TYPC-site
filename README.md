# TYPC-site

Personal research journal and website for 藏书小刊. The public pages are generated by Astro; guestbook messages and submissions are stored in Cloudflare D1 and moderated before publication.

## Local development

```bash
npm install
npm run dev
```

`npm run dev` previews static pages. To test the guestbook, submissions and moderation APIs locally:

```bash
copy .dev.vars.example .dev.vars
npm run build
npm run db:migrate:local
npm run dev:worker
```

Local moderation is available at `/review/` using the token stored in `.dev.vars`.

## Update content

Add Markdown files under:

- `src/content/blog/`
- `src/content/essays/`
- `src/content/resources/`
- `src/content/bookmarks/`
- `src/content/downloads/`

Each file needs frontmatter:

```md
---
title: "Post title"
description: "Short summary"
date: "2026-05-22"
language: "zh"
tags: ["note"]
---
```

## Deploy

The site runs as a Cloudflare Worker with static assets and a D1 binding.

One-time production setup:

```bash
npx wrangler login
npx wrangler d1 create typc-site-content
```

## English version

The English site lives under `/en/`. English translations are stored in matching folders under `src/content-en/`.

For the language switch on an article to open its matching translation, keep the same filename/slug in both languages. For example:

```text
src/content/blog/260614.md
src/content-en/blog/260614.md
```

English entries use `language: "en"`. The current bilingual structure covers the home page, all public sections, search and every existing article.

Copy the returned database ID into `wrangler.jsonc`, then configure a long random moderation token and apply the schema:

```bash
npx wrangler secret put ADMIN_TOKEN
npm run db:migrate:remote
```

Build and deploy:

```bash
npm run deploy
```

Use Node.js 22 or newer. Never commit `.dev.vars` or the production admin token.

## Admin CMS

The admin page lives at `/admin/` and uses Decap CMS.

Before it can save changes on the live site, configure GitHub OAuth for the
repository and set the CMS backend OAuth endpoint in `public/admin/config.yml`.
The content edited in the CMS is committed back to GitHub, then Cloudflare
rebuilds the site automatically.

Visitor messages and submissions are reviewed separately at `/review/`. Approving a guestbook message makes it visible immediately. Approved submissions remain in the review queue; use “复制 Markdown 稿件” and finish publishing through Decap CMS so editorial content continues to be versioned in Git.
